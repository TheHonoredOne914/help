# ORASAKA VPN — состояние сайта

Папка: `orasaka-site/` (Next.js 16 App Router + TypeScript strict + Tailwind 4 + Motion 12). Telegram-бот: [@orasakavpn_bot](https://t.me/orasakavpn_bot).
Код BestDel в корне репозитория, бот, FastAPI, Remnawave и VPS не изменялись. Реальных платежей нет.

Запуск полного demo-потока:

```bash
cd orasaka-site && npm ci
SITE_MODE=demo DEMO_FIXTURES=test PAYMENTS_MODE=mock npm run dev   # http://localhost:3000
npm run check && npm run build                                     # typecheck + lint + 24 теста + сборка
CHROME_PATH=/usr/local/bin/google-chrome npm run test:e2e           # 21 Playwright-тест (поднимет dev-сервер сам или переиспользует :3000)
```

`CHROME_PATH` нужен, только если браузеры Playwright не скачаны (`npx playwright install chromium`).

Контракт для backend — [`API_CONTRACT.md`](./API_CONTRACT.md).

## 0. Итерация 3 — интерактивный фон, курсор, брендинг

**Референс.** https://milanko.shop/ загрузился и изучен в браузере только как планка качества интерактива: фон реагирует на мышь и скролл, есть глубина и плавные смены композиции между секциями. Дизайн, разметка, графика и код не копировались — вся графика ORASAKA своя (процедурная).

**Палитра:** фон `#080809`, вторичный `#111114`, красный `#E50914` (`--color-brand`), яркий красный `#FF2035` (`--color-accent`), белый `#F5F5F5`. Заливка кнопок `#D80A14`: на ней белый текст проходит WCAG AA.

**Интерактивный фон** (`src/lib/fx/background-engine.ts`, `src/components/fx/cyber-background.tsx`). Технология — Canvas 2D, без библиотек. WebGL не нужен: эффекты — линии, частицы и градиенты, а у Canvas 2D нет потери контекста и шейдеров, и он есть везде.

Слои (сзади вперёд):
1. Глубина и красные световые пятна.
2. Дальний и ближний планы — оригинальные силуэты японско-футуристичной архитектуры: башни, ярусные крыши, ворота, неоновые полосы.
3. Мягкий свет под курсором.
4. Почти невидимая сетка с метками-крестами: возле курсора линии загораются красным, по ним бежит световая волна, вершины слегка отталкиваются.
5. Световые линии: ускоряются от скорости скролла и плавно возвращаются к обычной скорости.
6. Пакеты данных по линиям сетки (страница подключения).
7. Красные частицы: отталкиваются курсором и возвращаются к своему дрейфу.
8. Клик — угловая волна: надрезанный октагон и 4 засечки, без круглых пузырей.

Скролл смещает глубину и параллакс силуэтов. Сцены переключаются плавно:

| Сцена | Где | Что преобладает |
|---|---|---|
| home | `/` | свет и частицы |
| pricing | `/pricing`, `/checkout` | сетка и световые линии |
| connect | `/connect`, `/devices` | движение данных |
| account | `/account`, `/payment`, `/pay` | спокойно |
| calm | остальные страницы | спокойно |

На главной сцена меняется по секциям: у каждой секции есть атрибут `data-scene`.

**Производительность фона:**
- Статичные слои пререндерятся во offscreen-canvas при resize.
- `requestAnimationFrame`; анимация не зависит от частоты кадров.
- DPR не выше 1,5.
- Адаптивное качество 0–2: начальное — по устройству, дальше по измеренному времени кадра (понижается при ~24 мс/кадр, медленно восстанавливается).
- 30 fps в простое и на слабом качестве; пауза на скрытой вкладке.
- Мобильные: меньше частиц, без деформации сетки.
- `prefers-reduced-motion`: один статичный кадр.
- Если Canvas недоступен (`html[data-fx="fallback"]`), остаётся статичный CSS-слой `.fx-static`.
- Фон не перехватывает ввод: `pointer-events: none`, `z-index < 0`.

**ORASAKA CYBER CURSOR** (`src/components/fx/cyber-cursor.tsx`) — только при `(hover: hover) and (pointer: fine)`.
- Форма: собственный асимметричный угловой указатель из острых сегментов с неоновым свечением.
- Состояния:
  - на кнопках и ссылках — прицел;
  - клик — короткий ромбовидный импульс;
  - на интерактивных карточках — тонкая красная рамка с лёгким магнитным притяжением;
  - очень короткий след (90 мс).
- Позиция острия записывается синхронно в `pointermove` по точным координатам, без задержки и сглаживания.
- В полях ввода остаётся системный I-beam; выделение текста работает.
- Слой показан в top layer (`popover`), поэтому виден и над модальными диалогами.
- На touch курсора нет; при reduced motion отключены след, импульс и притяжение.
- Если курсор не инициализировался, возвращается системный.

**Карточки и кнопки.** `Tilt` (`src/components/fx/tilt.tsx`):
- лёгкий 3D-наклон за курсором;
- блик;
- красное свечение рамки.

Применён к карточкам главной, тарифов и устройств.

Кнопки:
- подъём при hover;
- свечение;
- сжатие при нажатии (`scale .97`);
- видимый фокус с клавиатуры.

**Брендинг.** Логотипа в ассетах нет, поэтому оставлен текстовый знак с новой угловой эмблемой — она же favicon (`src/app/icon.svg`). Мобильное меню фирменное: нумерация 01–06, контурная катакана, красные акценты, анимация открытия (только transform/opacity/clip, отключается при reduced motion).

**Оплата.** Шаги «Тариф → Способ оплаты → Заказ → Ожидание оплаты → Подтверждение» (`src/components/payment-steps.tsx`) на `/checkout`, `/checkout/[id]`, `/pay/mock/*` и `/payment/{return,success,error}`. Индикатор только навигационный: статус по-прежнему приходит с сервера. Платёжная архитектура и `API_CONTRACT.md` не менялись.

## 2. Готово

**Дизайн и анимации**
- Чёрно-красно-белый стиль японской киберпанк-мегакорпорации; шрифты Unbounded / Manrope / JetBrains Mono (кириллица).
- Hero: оригинальный баннер с героиней ORASAKA справа (целиком, `object-contain`, без искажений); слева заголовок ORASAKA VPN, описание и кнопки «Подключиться» / «Выбрать тариф»; побуквенное появление заголовка; «дыхание» изображения; scanline; HUD-метка «ORASAKA // NET»; 3D-наклон за курсором (только мышь, ≥1024 px); параллакс и затухание при скролле; бегущая строка; контурная катакана オラサカ. В итерации 3 убраны плавающие чипы (дублировали текст, нарисованный на баннере), кольцо и тяжёлые blur-слои.
- Секции /01–/06 с рисующейся линией-разделителем, reveal при скролле, полоса прогресса прокрутки, блеск на кнопках, hover-подъём карточек.
- Производительность: анимируются только `transform`/`opacity`; на мобильных размытие слабее, без наклона/параллакса/чипов; `prefers-reduced-motion` отключает движение (остаются только короткие fade); фоновые циклы на паузе при скрытой вкладке и по кнопке в footer.

**Страницы (21)** — `/`, `/pricing`, `/connect` (вкладки, `#android|#ios|#windows|#macos`), `/devices`, `/faq` (4 раздела с якорями), `/account`, `/checkout` (выбор срока и способа оплаты), `/checkout/[orderId]`, `/pay/mock/[paymentId]` (DEMO-шлюз), `/payment/return`, `/payment/success`, `/payment/error`, `/support`, `/legal/{offer,privacy,refunds,contacts}`, 404. Использованы баннеры `main`, `devices`, `tariffs`, `support`, `connect`, `instructions`, `cabinet`.

**Кабинет** — вход (demo), выход; подписка и статус выдачи; «Продлить»; ссылка подключения (маска / показать / копировать); устройства с отключением через диалог; история покупок со ссылками на заказы; сценарии demo.

**Платёжная архитектура** (`src/lib/payments/`)
- `PaymentProviderAdapter` (create / verify / validateWebhook / parseWebhook / refund?) и реестр провайдеров: mock (только demo), ЮKassa (`pending_integration`), crypto (`disabled`), Telegram Stars (`bot_only`). Новый провайдер = адаптер + строка в реестре.
- `PaymentService`: создание платежа с ключом идемпотентности, сохранённым **до** вызова провайдера; повторный клик → тот же платёж; `verifyOrder` — перезапрос у провайдера; webhook: HMAC + окно 5 мин + constant-time, дедупликация событий, тело webhook не доверяется (всегда re-fetch), сверка id / суммы / валюты / окружения.
- Заказ: монотонные статусы, snapshot цены на сервере, idempotent создание (ключ привязан к пользователю, конфликт при других параметрах), истечение через 30 мин, выдача доступа ровно один раз, `paid → provisioning_pending → active`. Отмена платежа оставляет заказ оплачиваемым.
- Страницы успеха/ошибки и возврата перечитывают статус с сервера; параметры URL (`?status=success`) игнорируются.

**API-клиент** (`src/lib/api/client.ts`) — `auth`, `plans`, `orders`, `subscription` (get / renew), `connection.getLink`, `devices` (list / remove). Две реализации: mock и live. BFF-маршруты: Origin-проверка мутаций, HttpOnly-сессия, `private, no-store`, лимит тела, заголовок `x-orasaka-source`.

**Проверено (этой итерацией)**
- `npm run check` (typecheck + lint + **24/24** теста) и `npm run build` — без ошибок.
- 19 маршрутов × 6 ширин (360, 390, 768, 1024, 1280, 1440) — без горизонтального скролла; навигация из 6 пунктов помещается на 1024 px.
- E2E в Chrome (Playwright), без ошибок в консоли:
  - вход demo; тариф → checkout (3 недоступных способа заблокированы); двойной клик → 1 запрос / 1 ключ; DEMO-шлюз → оплата → `/payment/success` «Подписка активна»;
  - продление → отмена на шлюзе → `/payment/error` → «Оплатить снова» → успех;
  - подделка `/payment/success?status=success` для неоплаченного заказа показывает «Платёж ещё не подтверждён»;
  - отмена заказа через диалог (Escape возвращает фокус); отключение устройства; сценарии demo; выход; `/connect#windows` открывает вкладку Windows.
- Запросы с чужим Origin → 403; неподписанный webhook → 403; webhook выключенного провайдера → 404.
- Найдено и исправлено: перенос «ORASAK / A» в hero на desktop; восстановление старого состояния страницы возврата из скрытого `Activity` (Cache Components) приводило к ложному переходу на `/payment/error` — редирект теперь срабатывает только после свежей серверной проверки.

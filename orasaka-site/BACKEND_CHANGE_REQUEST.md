# Пробел: учёт VPN и выдача доступа

Статус: **запрос к владельцу по живому VPN и боту**. Кода бота, FastAPI и Remnawave в этом репозитории нет. [`API_CONTRACT.md`](./API_CONTRACT.md) — черновик, не доказательство маршрутов. Сайт не пишет в базу бота и не заводит вторую базу пользователей VPN. Имена операций ниже — потребность, не найденные эндпоинты.

Локально уже работает файловая SQLite (`node:sqlite`, без отдельного сервера). `ORASAKA_DB_PATH` обязан быть абсолютным путём вне каталога релиза (пример `/var/lib/orasaka/site.sqlite`). Сайт и `npm run fulfill` открывают один и тот же путь. Резервная копия: `VACUUM INTO` складывает WAL в один файл; отдельный снимок копирует сам файл, `-wal` и `-shm`. Реальный файл базы в архив исходников не входит.

`ORASAKA_PROFILE=public` (также когда переменная пустая) — единственный профиль для публичного VPS. С `MAIL_MODE=dev` или `VPN_MODE=double` процесс не стартует. `/api/dev/mailbox` и `/api/dev/telegram-proof` в этом профиле отвечают 404 даже если флаги заданы. `ORASAKA_PROFILE=isolated` — только локальный `next start`. На публичный VPS его ставить нельзя.

Оплата на сайте по-прежнему выключена, пока на сервере нет `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` и `YOOKASSA_MODE=test|live`. Кнопка «Купить на сайте» заказ не создаёт. HTTP-адаптер ЮKassa умеет создать платёж и заново его прочитать. Тестовый магазин ЮKassa в этой среде не вызывался: ключей нет. Локальный HTTP в тестах — не магазин ЮKassa.

Почта: код хранится как HMAC-SHA256 и гасится атомарно. Отправка — nodemailer: TLS с проверкой сертификата, AUTH, таймауты, многострочные ответы. `MAIL_MODE=dev` пишет письмо только в локальный ящик и только в профиле `isolated`. Без настроенного SMTP почта выключена для любого адреса одним и тем же ответом. Боевой отправитель и домен ещё не заданы, поэтому настоящая доставка здесь не проверялась.

VPN: `VPN_MODE=double` — изолированный тестовый двойник, не действующий бот и не Remnawave. Пустой `VPN_MODE` — адаптер `unconfigured`: кабинет показывает, что подписка, история бота и устройства недоступны, и не рисует нули. Рабочие маршруты живого API не выдуманы.

Продление: новый срок начинается от `max(текущее окончание, момент выдачи)`. В коде доступны `calendar-months` и `fixed-day-blocks` (N×30 суток) для production; `test-30-day-blocks` — только isolated. Выбор владельца задаётся через `VPN_DURATION_RULE` на сервере. Ставки налогов и чеков в код не угадываются.

## Чего не хватает у бота и VPN

Эти операции сайт должен вызывать с сервера. Секрет — только в окружении сервера, не из браузера. Пока их нет, кабинет не подставляет фиктивные строки.

1. Найти пользователя по числовому Telegram id. Username и `sub` из OIDC ключом не являются. Если пользователь уже есть в боте, вернуть его существующий `vpn_user_ref`, а не создавать нового пользователя VPN.
2. Найти или создать пользователя по подтверждённому email. Один пользователь на один подтверждённый адрес.
3. Выдать доступ по оплаченному заказу идемпотентно по `orderId`. Повтор того же заказа срок не удлиняет.
4. Продлить существующую подписку тем же способом. Отличать «уже выдано» от «временно недоступно» и от «пользователь не найден».
5. Прочитать для владельца сессии: активна ли подписка, срок, дата окончания, остаток, ссылку подключения. Ссылку не писать в логи, аналитику и публичные URL. Чужой аккаунт её не получает.
6. История покупок бота, только чтение, с пагинацией: дата, сумма, срок, статус, источник. Не восстанавливать покупки из одной даты окончания. Если старая история недоступна, нужен явный ответ «истории нет», а не пустой успех, который сайт примет за «покупок не было».
7. Список устройств владельца: название и платформа, если они есть, последняя активность, занятые места и лимит. Число TCP-соединений и IP — не число устройств.
8. Число онлайн только если есть телеметрия, и вместе с ней — что считается «онлайн» и насколько данные свежие. Если телеметрии нет, сайт пишет «Статус онлайн недоступен», а не 0.
9. Отключение устройства — только если есть безопасный вызов и пользователь подтвердил. Пока вызова нет, кнопки в кабинете нет.

Ошибки, которые сайт должен отличать: нет такого пользователя, заказ уже выдан (не ошибка), временная недоступность (повтор).

## Вход через Telegram

Официальный браузерный вход подключён в коде и не включается без серверных значений.

- Текущий поток Telegram — OIDC (`https://oauth.telegram.org`). Нужны `TELEGRAM_LOGIN_CLIENT_ID` и `TELEGRAM_LOGIN_CLIENT_SECRET` из BotFather → Login Widget. Это не токен Bot API. Сайт проверяет RS256, `iss`, `aud`, `exp`, `nonce` попытки входа, одноразовость `id_token`. Личность — числовой claim `id`.
- Старый виджет — `TELEGRAM_BOT_TOKEN` и публичный `TELEGRAM_BOT_USERNAME`. Токена одного недостаточно. Хеш считается как у виджета, попытка входа привязана к cookie браузера, повтор того же хеша отклоняется.
- Без этих значений кнопка говорит «Вход через Telegram не подключён» и не вызывает `/api/dev/telegram-proof`.

Ни OIDC, ни виджет против `oauth.telegram.org` здесь не вызывались: client id, client secret и токен бота не заданы. Локальная проверка подписи на своём ключе — не вход покупателя бота.

## Почта и прокси

Лимит по адресу — 5 писем в час, отдельно от лимита по IP — 20 в час. Перед сайтом nginx должен подменять заголовок, а порт приложения не должен быть доступен из интернета:

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
```

Не `$proxy_add_x_forwarded_for`. `TRUST_PROXY=1` читает заголовок только когда в нём один адрес. Список адресов не открывает новый лимит. Пустой `TRUST_PROXY` заголовок игнорирует.

## ЮKassa

Магазин не подключён. Секрет в репозиторий и в чат не кладётся. Когда магазин будет: редирект на страницу ЮKassa, сумма только из снимка заказа (`200.00`, `500.00`, `900.00`, `1600.00` RUB), заголовок `Idempotence-Key` сохраняется до HTTP-вызова и повторяется после таймаута. Webhook — повод заново запросить платёж и сверить магазин, сумму, валюту, `test`, статус и заказ. Возврат покупателя на сайт оплату не подтверждает. Тестовый платёж в режиме `live` отклоняется. HMAC для уведомлений ЮKassa не выдумывался.

Чеки и ставку не задавать, пока неизвестен статус продавца.
